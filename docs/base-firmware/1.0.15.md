# Base firmware 1.0.15

Adds opt-in OTA to Reverse TFT Feather using D1 active-HIGH/Pull.DOWN recovery
at hard reset. The held button leaves host USB write access and prevents OTA
loading; D9 remains the FeatherWing Hold LED. XIAO D9 active-LOW recovery is
unchanged. Unknown boards remain in normal USB mode. Concurrent filesystem
writes remain prohibited. Initial enrollment/opt-in and approved-version target
assignment are explicit per device; publishing never advances existing targets.

Compatibility loader 1.1.0 supports legacy XIAO API1 and new API2 manifests.
API2 supports explicitly listed known boards, records API/board with each trial,
and requires matching namespace API/version and UI interface. Legacy journals
without new metadata are interpreted as XIAO API1. Existing release bytes and
assignments remain immutable. Server API2 assignment/serving require enrolled
board identity and the latest matching board/base report (base >=1.0.15).

Application 1.1.0/API2 owns TFT rendering, website-view timeout and button view
policy. The base samples/debounces pins, persists reboot intent through a narrow
Platform callback and owns every output write and hold lease. device_display.py
is a small compatibility import of the root USB recovery application's helpers;
it no longer duplicates renderer code. The selected OTA application's renderer
handles normal operation. Root provisioning/recovery remains available without
a working OTA app. GPIO mapping, hold deadlines and certificate checks are
unchanged. Base and app versions remain independent.

Maintenance and OTA reports include board_id. Setup restart defers while an OTA
trial is pending; a previously durable reset marker suppresses OTA startup and
its watchdog until setup ACK recovery completes. Existing credentials, confirmed
slots, journals, sequence floor and OTA token settings survive setup restart.

Host tests cover API2/legacy validation, metadata, active-hold deferral, button
policy, actual selected-version reporting, rollback on UI-construction failure,
D1 recovery polarity, protected pin cleanup and board-specific USB provisioning.
Physical results and remaining qualification limits are recorded after testing.

Initial USB installation on 37cc02 (CP 10.3.2) passed native API2 renderer/button
view and Feather manifest checks. Actual app/base reported 1.1.0/1.0.15 and
Wi-Fi/MQTT reconnected with preserved NVM. Validation: 135 host, 55 web/backend
unit, 87 browser (one existing WebKit skip), 31 actual local Firestore tests,
and pre-commit hooks passed. Physical OTA boot/D1 recovery, TLS installation/
confirmation, invalid-Python and UI-failure rollback, watchdog recovery, and
isolated truncated-journal recovery
subsequently passed. The approved application is confirmed at sequence 6.
See `docs/feather-ota-bench-validation.md` for evidence and qualification limits;
physical power-loss and live gate/hold behavior remain unqualified.
