# Base firmware 1.0.4

Multiple local Wi-Fi profiles (up to five), add/update/forget in the captive
portal, offline Drawbridge branding using the existing castle SVG geometry,
and explicit Feather D1 startup entry into setup. D1 is read as an active-high
input with pulldown and released; XIAO D1 remains its MQTT status output.
Setup initializes D10 LOW and never starts the MQTT command loop. Saved-network
failures continue station retries, without automatically opening a setup AP.

GATE1/GATE2/GATE3 single-network records remain readable. Profiles migrate when
modified; MQTT identity, registration and unrelated fields are preserved.
The GATE3 length-prefixed record may use up to 4096 available NVM bytes; size
validation precedes writes. Last-successful network changes persist once.
Password fields are never prefilled or rendered; portal assets are inline.

USB validation: run host tests and all-files hooks, install to the Feather,
verify the original network and identity survive, check automatic connection
and passive heartbeat stability. D1 physical startup entry and a second network
need interactive checks. No live gate activation is part of installation.

USB installation observed 2026-11-16 on 37cc02 / CircuitPython 10.3.2:
app 1.0.1 and base 1.0.4 start with OTA disabled and transistor output LOW.
Before/after NVM SHA-256 matches. At this location the original saved network
is unavailable; station attempts retry with bounded failures and no crash.
Host suite: 86 tests pass. Portal phone preview has no horizontal overflow.
Registration screen now places QR on the right and the D1 + RESET / Add Wi-Fi
hint on the left, with a four-module QR quiet zone. Physical button entry,
second-location save, QR scanning and online MQTT remain interactive checks.
