# Base firmware 1.0.11

Correct the Reverse TFT Feather's GPIO mapping to match the fabricated
FeatherWing: Wi-Fi D5/GPIO5 (J2.10), MQTT D6/GPIO6 (J2.9), Hold D9/GPIO9
(J2.8), and transistor control D11/GPIO11 (J2.6). The earlier Feather branch
used virtual status indicators and incorrectly inherited XIAO's D10 control
alias. D0/D1/D2 remain buttons; XIAO retains D10/D0/D1/D2 and its original
polarity and OTA maintenance behavior. Hold edge logs name the actual pin.

J3 is open collector: an active hold drives the transistor base HIGH and sinks
OUT_OC toward GND. It does not supply a HIGH voltage at the screw terminal.
The green D3 indicator flashes independently at four cycles per second during
a hold; indicator servicing never changes the transistor control output.

Normal screen uses a forest-green Drawbridge header, device ID, cream
background and separate Wi-Fi, MQTT and Hold rows. Hold ON/OFF is enlarged;
connection state remains text as well as color. Registration QR is unchanged.

Validation: failing-then-passing GPIO mapping and screen regressions; complete
host suite and pre-commit checks. USB validation and passive online/indicator
observations are recorded in artifacts/circuitpython-install. Physical LED
brightness and open-collector terminal voltage need user observation/meter;
software GPIO logs do not establish electrical behavior. No automated hold
is sent during deployment.

Installed on Feather 37cc02 with application 1.0.1 / CircuitPython 10.3.2.
Boot log reports base 1.0.11 and the installed files match source. User confirmed
the new screen looks good. All 97 host tests and pre-commit checks passed.
The post-install 70-second passive check passed with seven online heartbeats,
increasing alive counts, steady Wi-Fi/MQTT indicators, control LOW and hold OFF.
No hold was issued during this observation, so it contains no D9 edge samples
and does not validate physical LED illumination or J3 electrical behavior.
