# Base firmware 1.0.10

Secure QR enrollment for the connected Reverse TFT Feather. Persist a random
private pairing secret in NVM, place only its SHA-256 derived code in a compact
QR URL fragment, and send the private proof only in TLS device request bodies.
The compact alias redirects to the canonical Firebase auth origin. MQTT
credentials never enter QR/browser URLs. Credential delivery is retryable;
retain the private proof for device acknowledgment and interrupted delivery.

The screen shows Wi-Fi connection, waiting/checking registration, credentials
saved, MQTT connection and acknowledgment progress. A fresh backend claim is
completed only after credentials are saved and the device has subscribed to its
exact MQTT command topic; the successful ack is persisted. Retries never run
while holding the gate. Existing XIAO pin assignments, OTA restriction and
already configured legacy MQTT devices are unchanged. QR quiet zone is four
modules on every side; compact URLs permit larger modules on the small screen.

Validation: host proof/URL/persistence/ack/display regressions, actual device
hashing/QR/form/NVM compatibility checks, complete web/emulator suite, production
auth/API checks and passive hardware observation. Real Google sign-in and phone
QR scan/claim remain interactive; no gate commands are used for testing.

Installed on Reverse TFT Feather 37cc02 with application 1.0.1 and CircuitPython
10.3.2. Native validation confirmed the SHA-256 helper, 106-byte compact QR,
49-module matrix including four-module quiet zone, and both saved networks.
Full Functions/Hosting/rules deployment completed; live checks passed all three
canonical/OAuth entry paths and unauthenticated API rejection. User subsequently
confirmed successful QR registration. FeatherWing GPIO mapping is corrected
separately in base 1.0.11; the 1.0.10 screen's hold status did not establish
electrical activation.
